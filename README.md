# VoxelAir 多方航路预约台

VoxelAir 为共享同一沙盒的运营商登记起飞前预约。每家可以给整份预约报价，也可以将它设为不可买断。买方先看其路径上每份预约的持有人和补偿，再决定买断、等待或改道。四个演示角色是实例，协议按钱包和预约编号识别参与方。

## 演示

打开 index.html 逐笔回放四个演示钱包的真实交易。要用自己的钱包，运行 `node serve.cjs`，在启用了 EVM 扩展的浏览器打开 http://127.0.0.1:4178/ 并切换到“钱包实操”。RPC 与区块浏览器使用 Monad 测试网，链 ID 为 10143。

## 用不同运营商的钱包实操

1. 各家选择同一未来分钟（建议至少提前 10 分钟）。每家分别连接自己的钱包，输入格号和整份预约报价，点“读取占用与报价”，检查后预约。不同电脑和不同会话读取相同链上状态。
2. 买方输入意向格号，可以任选一份自己的现有预约随成交释放。每次改动意向后重新读取。钱包界面逐份列出收款方、重合格和报价。遇到不可买断预约时会显示阻塞并禁止支付；调整格号可重新核价。
3. 空闲路径直接预约。买断路径必须照预览中的预约编号和总额成交；签名期间预约被撤销、被别人买断或进入锁定窗口，交易整体失败。网络收取已广播失败交易的 gas。若两名买家争同一份预约，以链上确认的顺序为准。
4. 在“管理所选旧预约”内可以释放本方预约或标记已起飞。出发前 90 秒锁定；起飞标记也会禁止让渡。选择不同高度层可看同一时段另外 16 个格。核对网格时边框淡黄代表意向路线，橙色代表阻塞。

## 协议取舍

- **交易单位**是一整份预约。即使只重合一格，卖方整份旧预约也被释放。多个不同预约属于同一家公司时，各份分别结算。未重合的其他预约不受影响。一笔订单支持最多 16 格、最多 16 份卖方预约，买方可同时释放一份本方备选。
- **结算一致性**。买方提交精确预约清单与精确金额。合约重新检验占用、让渡状态和截止时间。向任意一位卖方付款失败，所有格、旧预约和已经执行的赔付一并回滚。未设置平台资金托管。
- **到期、数据和权责**。每格由 x、y、z 及一分钟时段确定；同一条 MVP 航线的全部格子占相同一分钟。后续若要表达逐段进入不同时间窗，需要扩展预约结构。真实飞行状态依靠运营方申报；沙盒预约不构成飞行许可。公开链可见地址、网格、价格和时段，演示使用合成数据。
- **市场公平**。当前没有运营方资质、押金、爽约罚则或单方配额。有资金买断不等于有法定优先级，医疗应急优先权应由沙盒规则单独定义。试点前还需验证运营商是否愿意报出有约束力的价格、卖方能否取得可接受的替代时段，以及免费占位是否会造成囤积。
- **性能**。已经检验合约的排他和原子结算；本轮未做城市级压力测试，也未测量钱包交互到最终确认的延迟分布。
- **单笔成本**。本次多方买断的回执记录了 430,851 gas，有效 gas 单价 102 gwei。网络费为 0.043946802 测试 MON，约为演示补偿总额 0.01 的 4.39 倍。测试币不能换算出真实企业成本。若产品承诺低摩擦微额赔付，需要结合有效报价、gas 单价、按单或批量结算的时效要求另行验证。

## 合约回归

VoxelAirMarket.sol 复用 VoxelAir.sol 的占格、释放和锁定校验。测试编译器为 Solidity 0.8.30，优化器开启并指定 Paris EVM。安装开发依赖 ganache@7.9.2，准备 solc 或将 SOLC 环境变量指向编译器，再运行 `node --test tests/market.test.cjs`。覆盖重复命中只赔一次、拒收款回滚、报价不符、预约列表失效、释放他人预约失败、两个买方的先后竞争、起飞标记以及锁定窗口。生产页面无须安装开发依赖。
